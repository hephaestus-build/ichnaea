Ichnaea gives a verdict only from a method that is validated for your design.
This page says what that word means, and what is validated today.

## The bar

A method is validated when all of these hold:

1. **A written bar.** A 95% bound must cover the true difference at least 94% of the time at each grid point. On average it must cover 95%. A 5% test must reject a true null at most 5% of the time.
2. **A stated grid.** The studies cover named numbers of cases, trials, pass rates and changes. A result outside the grid is outside the validated domain.
3. **Exact where possible.** Where a value can be computed exactly, it is. Elsewhere, simulations screen every point and confirm the doubtful ones with about 200,000 repetitions.
4. **Independent checks.** Results match the R package ratesci and R's exact Mantel–Haenszel test.
5. **In CI.** The studies run on every pull request and every night. A change that breaks the bar fails the build.

## What is validated today

| Method                                                                     | Status                                                                                                                                               |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Regression for pass/fail measures, 2 or 3 trials per case, 5 or more cases | Validated. The worst measured type-I error is 0.0454 against a bar of 0.05.                                                                          |
| Regression at one trial per case, 5 or more cases                          | Validated when the records pass three checks: a random order within each pair, both trials of a case run close together, and two clean noise checks. |
| Pass (non-inferiority), at any number of trials                            | Not validated. The smallest validated limit is not set.                                                                                              |
| Measures with scores                                                       | A test exists and matches its reference values. Its type-I study has not run, so it gives no verdict.                                                |

## False alarms, measured

A false alarm is a Regression when nothing changed.
The studies run comparisons with no change and count how often the test rejects. The bar is 5%.

| Test                                             | Grid                           | Worst false-alarm rate | Mean  |
| ------------------------------------------------ | ------------------------------ | ---------------------- | ----- |
| Exact stratified test, equal trial counts        | 45 points, 28 computed exactly | 3.95%                  | 2.22% |
| Permutation test, 17 cases, unequal trial counts | 6 points                       | 4.14%                  | 2.87% |
| Permutation test, 60 cases, unequal trial counts | 6 points                       | 4.54%                  | 3.92% |
| Exact test at one trial per case, 5 to 300 cases | 431,983 structures, all exact  | 3.92%                  | —     |

A fixed rule such as "block when the score falls by 3 points" has no such bar.

## What validated does not mean

- **A search, not a proof.** A study covers the structures it tried. A structure outside them may still fail.
- **These cases only.** A validated result is about the cases in your suite, not about new inputs.
- **Not your setup.** Validation covers the method. A [noise check](/ichnaea/explanation/noise-checks/) shows whether your pipeline gives false alarms.

## How the card shows it

A number from a method that is not validated always says so.
Until the smallest limit is set, every bound is labeled "not validated".
A verdict never rests on a result that is not validated.
