Ichnaea is on npm as `@tumaet/ichnaea`.
Each version is staged by the release workflow, and a package owner approves it on npm.
Release candidates are available under the `next` tag.

## You need

- Node 24.3 or later
- pnpm, which the install test uses
- a project with a `package.json`

## Install

At the root of your project, run:

```sh
pnpm pkg set type=module
pnpm add @tumaet/ichnaea@next zod@4.6.7
npm audit signatures
```

The first command makes your project an ES module project, because the command line tool loads your configuration as an ES module.
The second adds Ichnaea and zod. Each release is tested with zod 4.6.7.
Ichnaea uses the copy of zod at the root of your project.
The third checks the signatures, as the next section says.

Your lockfile now pins the version.
Installing the package runs no script, because its `package.json` has none.
Check that the command line tool runs:

```sh
pnpm exec ichnaea --version
```

A pre-release has the dist-tag `next`, so you can also add it by its exact version, for example `pnpm add @tumaet/ichnaea@0.1.0-rc.1`.

## Check what you installed

`npm audit signatures` checks that the registry signed every installed package, and that each provenance attestation is valid.
It does not check who built a package or from which commit.

After an owner approves a version, Ichnaea's finish workflow checks more before it creates the version's GitHub release:

- The provenance names `.github/workflows/release.yml` at the version's `v*` tag.
- The provenance names the tag's commit, and that commit is on `main`.
- npm serves the exact tarball that the release workflow staged.

So install a version that has a [GitHub release](https://github.com/hephaestus-build/ichnaea/releases).
The release holds the same tarball, its SBOM `sbom.cdx.json`, and `SHA256SUMS`.

To check the commit yourself, read it in the provenance, which the version's page on npmjs.com links.
Then, in a clone of Ichnaea, run:

```sh
git merge-base --is-ancestor <commit> origin/main && echo "on main"
```

## Update

```sh
pnpm add @tumaet/ichnaea@next
npm audit signatures
```

## Work on Ichnaea and your project together

1. In the Ichnaea checkout, build on every change:

   ```sh
   pnpm --filter @tumaet/ichnaea build --watch
   ```

2. In your project, link the package of that checkout:

   ```sh
   pnpm link <path-to-ichnaea>/packages/ichnaea
   ```

3. When you are done, remove the link and install the pinned version again:

   ```sh
   pnpm unlink @tumaet/ichnaea
   pnpm install
   ```

Do not commit the link. It changes your `package.json` and lockfile to a path on your machine.

## Why every version needs an owner

A version on npm cannot be taken back.
So no workflow, token or person with write access to the repository can publish one alone.
The release workflow only stages a version.
A package owner approves it on npm with two-factor authentication.
[Decision 0021](https://github.com/hephaestus-build/ichnaea/blob/main/docs/decisions/0021-npm-staged-publishing.md) gives the chain.
