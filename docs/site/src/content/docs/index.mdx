## What Ichnaea does

You change a prompt, a model or your code.
Ichnaea compares the old configuration (the base) and the new one (the candidate) on the same cases.
It tests the difference case by case and gives one of four verdicts.

<CardGrid>
  <Card title="Regression">
    The candidate is worse on these cases, or a hard check failed. A CI job can block the change.
  </Card>
  <Card title="Pass">
    The candidate is not worse than the base by more than a limit that you set before the run.
  </Card>
  <Card title="Inconclusive">
    Your cases cannot decide. The card says why, for example that too few cases were run.
  </Card>
  <Card title="Invalid">
    The run cannot be trusted. For example, the two configurations differ in more than you declared.
  </Card>
</CardGrid>

Each verdict comes with its reason in words.
The exit code tells a CI job what to do: 0 to continue, 1 when the policy blocks, 2 for an error.
A trial that did not complete (an infrastructure failure, or output that was not captured) stays visible as missing. Ichnaea never counts it as a failure of your system.

## Why not a fixed threshold

A common gate blocks a change when the score falls by 3 points.
Models answer differently from run to run, so that gate fires even when nothing changed.

Take a suite of 12 cases with 3 trials each. 10 cases always pass, and 2 pass 70% of the time.
Compare the system with itself in 10,000 simulated runs:

- the fixed 3-point gate blocks 17.6% of the runs
- Ichnaea reports a Regression in 1.5% of the runs

Every one of those alarms is false. Try your own suite in the [planning explorer](/ichnaea/planner/).

## What it is not

- It does not host anything. Ichnaea is a TypeScript library and a command line tool.
- It does not rank models on public benchmarks.
- It does not run your system yet. You bring results from your own runner. A runner of its own is planned.

## Where your data goes

Ichnaea:

- listens on no port
- makes no network call of its own
- writes only where you tell it
- labels every field with a data class
- does not enforce where data goes

No built-in command moves data. The code holds an egress gate that denies by default, but nothing calls it today.

## Status

Ichnaea is 0.x. It is not on npm before 1.0.

| What                                                                               | Status                                                                 |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Regression for pass/fail measures, with 2 or 3 trials per case and 5 or more cases | Validated                                                              |
| Regression for pass/fail measures, with 1 trial per case and 5 or more cases       | Validated when the records pass the order, timing and noise checks     |
| Pass                                                                               | Not validated yet. An unchanged candidate gets Inconclusive, not Pass. |
| Measures with scores, and model judges                                             | Estimates only. They give no verdict.                                  |
| Judge calibration                                                                  | Planned: today only its schemas exist.                                 |

The [statistics validation](https://github.com/hephaestus-build/ichnaea/blob/main/packages/ichnaea/src/stats/VALIDATION.md) gives the evidence for each row.
